# 架构改进推进表

以下是待推进方案，均不代表已实施。每项确定负责人后，在本表补关联 issue、业务提交和验收记录。

| 阶段 | 交付物 | 验收门槛 | 状态 |
| --- | --- | --- | --- |
| 1：合同盘点 | SI、Scada、ScadaP2 各选一个常用模块，记录 Action/连接/过程/flag/参数/结果/权限 | 过程定义与调用方一致；覆盖正常、空、错误、未知 flag | 待团队选试点 |
| 2：风险边界 | 服务端身份、过程与操作授权、下载归属及规范化路径方案 | 身份伪造、跨用户、越界访问被拒绝；旧正常业务回归通过 | 待方案与测试环境 |
| 3：失败传播 | SQL error 表、导出 Failed、前端空值与错误显示兼容方案 | SQL 失败不再表现为成功，旧调用方分批迁移 | 待试点 |
| 4：前端样板 | 经过验证的列表/Form/日期/下拉/Tab/弹窗样板 | 目标终端尺寸、资源依赖、发布清单和保存刷新验证 | 待试点 |
| 5：模块边界 | WebApi/Proxy 与通用过程的选型准则及迁移 ADR | 明确身份边界、部署步骤、兼容期、回退及量化收益 | 待前四阶段证据 |
| 6：双平台对照 | 广州/东莞目录、组件、接口、SQL、配置差异矩阵 | 不以同架构推定同合同；两端分别留证据 | 尚未分析东莞 |

## 每个模块的合同卡

记录：平台及源码提交 → 页面路径/URL/布局 → 参考页 → HTTP 方法与 Action → 连接名 → 过程完整签名 → flag 矩阵 → 参数来源 → 返回数据形状/成功值 → 可信身份与数据权限 → 重复提交/事务 → 发布/回退 → 验收结果。

风险修复的回退不能简单恢复已确认漏洞。出现兼容问题时，应考虑关闭受影响入口或回退至仍保留安全边界的版本，由负责人决定。
